# Scripts

- Usage of `run_notebooks.py`, `kaggle_bundle.py` and `export_kaggle_requirements.py` is in root `AGENTS.md` (Environment, Notebook runner, Kaggle bundles sections). This file covers operating Kaggle runs.

## Running Kaggle kernels
- Chained kernels (`kernels = [...]`): push the source, wait for COMPLETE (`status`), then push the dependent; `push` refuses otherwise unless `--force`. CPU kernels (`accelerator` none/absent) spend no GPU quota.
- Staged notebooks (`MLC_Notebook`, `categorisation`; all CPU kernels, so no GPU quota; `max_cpu_sessions = 5` in `experiments.toml` is a local safety limit): push `embed` (`MLC_Notebook` only), wait for COMPLETE, push the train shards (they run in parallel, up to the session limit), wait for all, then push `assemble`. Each push refuses until its `kernels` are COMPLETE. A shard that ends INCOMPLETE (budget reached, notebook still exits 0) is continued by adding a manifest entry (new name and slug, same env) that attaches the previous shard in `kernels` and lists its `{input:<slug>}/checkpoints` in `CHECKPOINT_INPUTS`; add the new shard to the assemble entry's `kernels` and `CHECKPOINT_INPUTS` too. Never change the identity env strings between stages.
- Slugs double as Kaggle titles: at most 50 characters including `-smoke` (so full slugs at most 44); `build` fails otherwise (`KAGGLE_TITLE_LEN`).
- Status calls: `Rate limited` replies are retried with bounded backoff, then the status is unknown. `push` refuses (without `--force`) a kernel whose sources are unknown, reporting 'could not read status' separately from 'not COMPLETE'. The session wait counts unknown statuses as active (with a warning) and treats kernels Kaggle reports as not accessible (never pushed) as inactive, re-checking them on every poll; calls are spaced. The wait is bounded by `session_wait_timeout_minutes` in `[kaggle]` (default 720): afterwards `push` exits non-zero naming the active or unreadable kernels and never pushes. `--force` bypasses the source gate entirely (explicit operator action; unsafe when statuses are unknown). The session limit is not safe against concurrent `push` invocations (no lock): run one at a time.
- Full pushes spend the weekly GPU quota (about 30 h; 12 h per session; `max_gpu_sessions = 2` in `experiments.toml`). Push full kernels only when the user asks, and in the order the user sets.
- After changing a notebook or the bootstrap: `build`, then `push --only NAME --kernels-only` (cells are embedded in the kernel; datasets are unchanged). Relaunch only the kernel that failed.
- Kernels run on Kaggle, not locally: closing the terminal or WSL does not stop them. A local wait-then-fetch loop dies with WSL; re-check `status` and restart the loop instead of pushing again.
- Wait for completion with a background loop on `kaggle kernels status <owner>/<slug>` (RUNNING/QUEUED means not done), then `fetch --only NAME`. The user expects results to be fetched as soon as a kernel finishes.
- Never put a short timeout on `fetch`: full outputs are large (the old monolithic mlc-notebook about 9.5 GB, mlcgeneral 7.1 GB, mlccs 1.3 GB; staged slugs: `<base>-embed`, `<base>-train-<shard>`, `<base>-assemble`).
- `fetch` overwrites same-named files in `runs/kaggle/<slug>/` but does not delete stale ones from an earlier version; compare file mtimes with the run's end before trusting a file.

## Reading kernel logs
- `runs/kaggle/<slug>/<slug>.log` is JSON: a list of `{stream_name, time, data}` (`time` = seconds since start). Parse it with `python3 -I` (isolated mode: fetched outputs are untrusted downloads; stdlib json is enough); never dump it whole.
- Failure markers: `Exception encountered`, `Traceback`; `BLOCKED:` lines are expected static skips. The last entry's `time` is the run duration.
- Typical full-run durations (2026-10, T4, monolithic runs, before the staged CPU kernels and single-threaded RF, so staged durations will differ): filter 0.9 h, MLCCS 1.5 h, MLCGeneral 6.8 h, MLC_Notebook 10.5 h (close to the 12 h limit). Rebuilt CPU kernels (2026-11): `msc-thesis-embeddings` 3.3 h, `msc-thesis-filter` 7.1 h (28 candidates plus 100 tuning evaluations). Run history: `notebooks/kaggle-runs.md`.
