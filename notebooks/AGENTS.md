## Shared pipeline library (leakage-free rebuild)
- Every notebook and the System must use these modules (pure; no nltk or embedder imports; tests in `notebooks/tests`), not their own cleaning, label mapping or splitting:
  - `textprep.py`: `preprocess_text` (thesis rule: remove URLs, emails, `@mentions`, `#hashtags`; collapse whitespace; nothing else) and `group_key` (duplicate identity: lowercased, punctuation removed, one leading `rt` stripped); bump `TEXTPREP_VERSION` when output changes.
  - `taxonomy.toml` + `taxonomy.py`: thesis hierarchy and Watson node -> label mapping (edit the TOML, not code); `watson_list`, `top_labels(wl, relevant, "two_step"|"one_step")`, `sub_labels(wl, parent)` (sub-level `other` is internal, dropped from System output), `classes(level)` (fixed order), `taxonomy_sha256`, `as_bool` (strict bool check; `_as_bool` kept as alias). One-step `other` covers irrelevant posts AND relevant posts without a mapped category: never derive relevance from it.
  - `splits.py`: one grouped, stratified train/test split with grouped inner folds for all stages. Groups = `group_key` plus prefix merging of truncated copies (`min_prefix`, default 40; `max_group_rows` cap fails closed). `build_split` (raises on an empty test split or inner fold), `write_manifest`/`read_manifest` (CSV + JSON sidecar), `verify_manifest` (call it before using a manifest, with the pinned `expected_seed` and `expected_manifest_sha256`; it recomputes grouping and rebuilds), `assign_split`, `balance_report` (per-label support by split and inner fold, rows and groups), and `frequent_labelsets` (the thesis >=20 label-set rule, computed on each fitting partition: inner-train folds for selection, full train for the refit).
  - `embeddings.py` + `embedders.toml` (embedder names, kinds, dims, env var names, encode options, parity tolerances; paths and hub ids come from the env): `embed(texts, embedder)` applies `preprocess_text` itself (callers pass raw text) and returns finite float32; GloVe = sum of lowercased-token vectors (OOV ignored, no known token -> zero vector). `Embeddings.ipynb` writes one immutable artifact per corpus (`corpus`, `cotov`) and embedder into `EMBEDDINGS_DIR` (`<corpus>__<embedder>.npy` + `.json`; rows keyed by row id, no labels or split). Contract for consumers: `load_artifact(dir, name, expected_row_ids=..., expected_fingerprint=...)` (verifies sha256s, shape/dtype/finite, TEXTPREP_VERSION; fails closed on any mismatch, on an `unresolved` fingerprint unless `allow_unresolved`, and on NON-PRODUCTION smoke artifacts unless `allow_non_production`), then `select(ids)` in the requested order (a missing id raises); join by row id, never fit anything on test rows, fit scalers per fold. Re-embed new text with the same `embed` and embedder fingerprint. Env: `EMBEDDINGS_DIR`, `EMBEDDERS` (subset), `EMBED_SAMPLE_ROWS` (smoke), `COTOV_CSV` (no id column: ids are `cotov-<csv row position>`, English rows only), `SPLIT_MANIFEST_SHA256` (pinned). Kaggle: CPU kernel `msc-thesis-embeddings` (output dir `embeddings`); downstream kernels attach it and set `EMBEDDINGS_DIR={input:msc-thesis-embeddings}/embeddings`.

## Environment variables
- `filter`, `categorisation`, `Train-Test split`, `Embeddings` read env vars (`load_dotenv()`, then `os.chdir(ROOT)`); values are in the local `.env` (see root `AGENTS.md`). The other notebooks use hard-coded or relative paths.
- Names seen: `ROOT`, `RANDOM_STATE`, `TEST_SIZE`, `TWEETS_CSV`, `SPLIT_MANIFEST_CSV`, `SPLIT_TRAIN_CSV`, `SPLIT_TEST_CSV`, `SPLIT_ALLOW_OTHER_SEED`, `TEMP_CATEGORIES_TRAIN_CSV`, `TEMP_CATEGORIES_TEST_CSV`, `ONE_STEP_CATEGORIES_TRAIN_CSV`, `ONE_STEP_CATEGORIES_TEST_CSV`, `COTOV_CSV`, `SPLIT_MANIFEST_SHA256`, `EMBEDDINGS_DIR`, `EMBEDDERS`, `EMBED_SAMPLE_ROWS`, `FILTERS_PERFORMANCES_CSV`, `OPTIMAL_FILTER_PICKLE`, `OVERWRITE`, `FILTER_SMOKE`, `FILTER_SMOKE_OUT_DIR`, `FILTER_ALLOW_NO_COTOV`, `CATEGORISATION_LEVEL`, `STAGE`, `CATEGORISATION_SMOKE`, `CATEGORISATION_SMOKE_OUT_DIR`, `CATEGORISATION_OUT_DIR`, `ALLOW_UNRESOLVED_EMBEDDERS`, `MODELS_DIR`, `MAPPINGS_DIR`, embedder paths (`SBERT_PATH`, `ATTACK_BERT_PATH`, `DISTILROBERTA_PATH`, `GLOVE_6B_{50,100,200,300}D_PATH`).
- `Train-Test split`: builds the single frozen grouped split with `splits.build_split` (seed `RANDOM_STATE` must be 42 and `TEST_SIZE` 0.2; other values fail unless `SPLIT_ALLOW_OTHER_SEED=1`, tests only). Writes `SPLIT_MANIFEST_CSV` (+ `.json` sidecar), `SPLIT_TRAIN_CSV` and `SPLIT_TEST_CSV` (all corpus columns plus `group`, `inner_fold`; sorted by `_id`; no index). It re-reads the files, runs `verify_manifest`, checks the CSVs against the manifest, prints the manifest sha256 to pin downstream, and prints thesis descriptives (group stats, conflicting-label groups, `balance_report` by label). It no longer writes `filter_*`/`categories_*`; labels come from `taxonomy.py`, not from this notebook.
- `filter` (leakage-free rebuild; logic `filtering.py`, tests `tests/test_filtering.py`, project values `filter.toml`: embedders, families, search spaces, `max_evals`, smoke overrides):
  - Inputs: `SPLIT_TRAIN_CSV`/`SPLIT_TEST_CSV` verified with `splits.verify_manifest` (`SPLIT_MANIFEST_CSV`, seed 42, pinned `SPLIT_MANIFEST_SHA256`); label = `taxonomy.as_bool(relevant)`; features = `embeddings.load_artifact` per embedder (`EMBEDDINGS_DIR`, corpus artifact, production only, unresolved fingerprints fail closed unless `ALLOW_UNRESOLVED_EMBEDDERS=1`), selected by row id. It embeds nothing.
  - Selection: 28 candidates (7 embedders x LR/GNB/RF/XGB, `StandardScaler`+classifier `Pipeline`, scaler fitted per fold) scored by grouped 5-fold CV on train only, folds = manifest `inner_fold` (`PredefinedSplit`); metrics are mean +- std of balanced accuracy (selection metric), accuracy, precision, recall, F1, ROC AUC (`predict_proba`). Best = highest mean balanced accuracy, ties: lower std, then name; the name is derived, never hard-coded.
  - Tuning: hyperopt TPE on the selected family's `[spaces.*]`, `max_evals` evaluations, objective = mean grouped-CV balanced accuracy on train; evaluation i uses `rstate=default_rng([RANDOM_STATE, i])`, so a resumed run follows the uninterrupted trajectory. Candidate results and every trial are checkpointed (`CHECKPOINT_DIR`, keys `filter-cv`/`filter-tune`; identity = code incl. `filter.toml`, split files, embedding sidecars/fingerprints, seed, device, library versions); the budget (`CHECKPOINT_BUDGET_HOURS`/`CHECKPOINT_MARGIN_MINUTES`) stops cleanly with status INCOMPLETE (exit 0, rest skipped); rerun on the same store (locally) or attach the earlier kernel's `checkpoints` via `CHECKPOINT_INPUTS` (Kaggle) to resume. Tuning only starts once all candidates are checkpointed.
  - Test guard: every fit/CV/selection/tuning function gets the train ids bound to its X (length, duplicates and test overlap checked; order bound by selecting features by id: `run_candidates` selects through `features(embedder, train_ids)`, the notebook passing `ARTS[e].select(ids)`) and the test ids, and raises `LeakageError` on overlap; test features are first selected after tuning. Final: tuned pipeline refit on all train rows, evaluated once on test (all metrics, prevalence, confusion matrix) with 95% percentile bootstrap CIs (`[bootstrap]` in `filter.toml`: `B`, `seed`; test resamples whole manifest groups, Cotov resamples rows as it has no groups). The untuned selected candidate is a pre-planned descriptive comparison, never used for choice.
  - CV scores (CSV, sidecar `cv_*_selection_diagnostic`) are selection diagnostics (best-of-28, optimistically biased); each is the mean (std ddof=1) over the 5 folds of the fold metric.
  - Outputs: `OPTIMAL_FILTER_PICKLE` (joblib) + `<pickle>.json` sidecar (embedder name/fingerprint, `TEXTPREP_VERSION`, manifest sha256, params, CV, test and Cotov metrics, library versions, pickle sha256), `FILTERS_PERFORMANCES_CSV` (per-candidate CV table, percent, `&`-separated). Write order: the Cotov precheck, labels and artifact load (texts digest checked) run before any write; pickle, CSV and sidecar are written to `<name>.tmp` and renamed to the final names (sidecar last) only after the Cotov evaluation succeeded or was explicitly blocked, so a failed run leaves no unvalidated filter at the production paths. The sidecar `status` is `complete` or `complete-cotov-blocked` (`FILTER_ALLOW_NO_COTOV=1`). Consumers (e.g. `SystemLabelAssignment`) must load the filter with `filtering.load_deployed_filter(path)`, which checks the pickle sha256 against the sidecar, refuses any status other than `complete*`, and returns `(model, metadata)`; never a bare `joblib.load`. `OVERWRITE` (default false) must be true to replace existing outputs; the manifest sets it.
  - Cotov: the deployed filter on the English rows' `cotov` artifact of the selected embedder (texts digest and fingerprint checked); the CSV (`COTOV_CSV`) supplies only the `Related` labels; if the CSV or artifact is absent a production run FAILS (no COMPLETE status) unless `FILTER_ALLOW_NO_COTOV=1`, which prints `BLOCKED:` and records `cotov: blocked` in the sidecar (smoke runs may skip it). Same CI and prevalence reporting as test. Never used for fitting or choice.
  - Smoke: `FILTER_SMOKE=1` (runner entry `filter smoke`) uses the `[smoke]` config (few candidates, `max_evals` 2), is marked NON-PRODUCTION, writes only under `FILTER_SMOKE_OUT_DIR` and refuses the production pickle/CSV names.
  - Kaggle: CPU kernel `msc-thesis-filter` attaching kernel `msc-thesis-embeddings` (`EMBEDDINGS_DIR={input:msc-thesis-embeddings}/embeddings`).
- `categorisation` (leakage-free Two-Step rebuild; logic `categorisation.py`, tests `tests/test_categorisation.py`, values `categorisation.toml`: levels, embedders, methods x classifiers, `min_labelset_count`, bootstrap, smoke). One parametrised notebook replaces `MLCGeneral`/`MLCCS`; the old notebooks are deleted (history in git).
  - Controls: `CATEGORISATION_LEVEL` (one of general, computer security, hardware, operating systems, software, one step; fails closed otherwise; the slug of `one step` is `one_step`), `STAGE` (`train`, `assemble`, `all`), `EMBEDDERS` (train shard subset; assemble rejects subsets), `CATEGORISATION_SMOKE`, `OVERWRITE`, `ALLOW_UNRESOLVED_EMBEDDERS`, `RANDOM_STATE`, the split vars with pinned `SPLIT_MANIFEST_SHA256` (checked with `splits.verify_manifest`, seed 42, before `prepare_level`), `EMBEDDINGS_DIR` (features only via `embeddings.load_artifact` bound to the manifest row ids; it embeds nothing), outputs `CATEGORISATION_OUT_DIR` (default `models/`: `categoriser_<level>.pkl` + `.json` sidecar, `categorisation_<level>_performance.csv/.json`).
  - Protocol: per level every embedder x candidate (method x classifier) gets one OOF prediction per eligible train row (one checkpoint per fold, keys `cat-oof`); a candidate whose fold fails is not fitted on its remaining folds (they are stored as skipped failures); per-label best candidate by pooled OOF F1, best embedder by composed OOF macro F1 (printed as OOF selection scores, optimistic); refit on all eligible train rows; one test evaluation (all eligible rows = primary, plus the thesis-comparable subset, group-bootstrap CIs conditional on the selected pipeline). Assemble fails on any failed candidate (the `FAILED` reasons are printed) and publishes only via staged files + sidecar last (`publish_categoriser`; load with `load_deployed_categoriser`). Checkpoint identity: `categorisation.py`/`.toml`, the shared modules, `MLC/*.py`, split files, all embedding sidecars, effective config, level, seed, manifest sha, library versions; the shard subset is not hashed, so shards and assemble of a level share it.
  - `one step` (One-Step top level; `kind` top, `scheme` one_step, `population` all): trains on ALL corpus rows (irrelevant and relevant-unmapped posts get `other`; population `all` is valid only with scheme one_step and vice versa, other combinations raise `CategorisationError`); the sub levels are the Two-Step ones. `evaluate_test` adds a `relevance` block per scope: predicted relevant = any non-`other` label predicted, score = max non-`other` score, implicit relevance (empty prediction = irrelevant; `other` never vetoes a real label; not equivalent to the binary filter, since relevant-unmapped posts have gold `other`), binary metrics vs gold relevance (`LevelData.relevant_test`) with group-bootstrap CIs, confusion counts, counts of empty predictions and of `other` + real predictions, prevalence and the recall on relevant-unmapped (gold relevant, labelset `other` only) and relevant-mapped rows; stored in the performance json and sidecar (`__relevance__` CSV rows).
  - Sparse levels: a fold without any labelset of >= `min_labelset_count` rows aborts the level in the data cell with a `SPARSE LEVEL` error (fail closed; hardware, operating systems and software may hit this).
  - Smoke: `CATEGORISATION_SMOKE=1` (runner entries `categorisation smoke` = general, `categorisation smoke computer security`, `categorisation smoke hardware`, `categorisation smoke operating systems`, `categorisation smoke software`) uses `[smoke]`, is NON-PRODUCTION, writes only under `CATEGORISATION_SMOKE_OUT_DIR` and refuses production output names.


## Staged, checkpointed runs (`categorisation`)
- `MLC_Notebook` is superseded by categorisation level `one step` and has no manifest entries; its history is in git and `kaggle-runs.md`.
- Stage env: `STAGE` (`categorisation`) = `train`, `assemble` or `all` (default; `all` trains then assembles in one session). Production runs use no other overrides.
- Units: `EMBEDDERS` (`categorisation`, train only) = comma-separated embedder names. Embedder names: `GloVe.6B.50D/100D/200D/300D`, `DistilRoBERTa`, `SBERT`, `ATT&CK-BERT`. Assemble rejects any subset (it must cover the full configuration).
- Checkpoints (`notebooks/checkpoints.py`): `CHECKPOINT_DIR` (default `./checkpoints`, gitignored) is the output store; `CHECKPOINT_INPUTS` (`:`-separated, globs ok) are read-only earlier stores. Identity (config, code and data hashes, module versions incl. the torch build tag) must match across stages, so all stages of a run use the same image and identity inputs:
  - Hashed: the `categorisation` config, code and data (only the shard subset, budget and `ALLOW_*`/`OVERWRITE` controls are excluded).
  - Not hashed: `ROOT`, file paths (split CSVs, `EMBEDDINGS_DIR`, `CATEGORISATION_OUT_DIR`), `STAGE`, `EMBEDDERS`, budget, `OVERWRITE` and `ALLOW_*` variables (embedding content is bound by the artifact sidecars and fingerprints).
- Budget (train): `CHECKPOINT_BUDGET_HOURS` and `CHECKPOINT_MARGIN_MINUTES` (the margin must cover the longest single fit); optional `CHECKPOINT_SESSION_START`, `CHECKPOINT_FINALISE_MINUTES`. When the budget stops training the status is INCOMPLETE, the notebook still exits 0 and assembly is skipped; rerun (or add a continuation shard, `scripts/AGENTS.md`) to resume.
- Assemble: fails closed if any candidate is missing or failed to fit; `categorisation` has no failed-candidate switch. `ALLOW_UNRESOLVED_EMBEDDERS=1` allows unresolved embedder inputs. Candidates impossible by design (e.g. PSt `pruning_value` above the largest labelset count) are stored as 'infeasible' records, printed as "infeasible by design", and do not block assemble.
- Non-production local overrides: `categorisation` uses `CATEGORISATION_SMOKE=1` (above). Never set it in the manifest except in the declared smoke entries.
- Kaggle: `experiments.toml` declares CPU kernels per stage (`categorisation`, slugs `msc-thesis-cat-<level>-train-<shard>` / `-assemble`, level `one step` uses slug base `msc-thesis-cat-onestep`: general and one step one shard per embedder, computer security GloVe and transformers shards, hardware, operating systems and software one shard each; general also has `-train2-<shard>` continuation shards (distilroberta, sbert, attackbert), which its assemble lists too; every assemble chains its shards, all chain `msc-thesis-embeddings`). Operating them: `scripts/AGENTS.md`.
